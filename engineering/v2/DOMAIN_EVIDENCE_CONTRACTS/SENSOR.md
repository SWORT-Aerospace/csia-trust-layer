# SENSOR — EVIDENCE CONTRACT (Phase C §3)

Generated by `engineering/v2/run_phase_c.py` from the live signature table, so it cannot drift from the code.

For each symptom this domain can explain: the mechanism, the alternative explanations, and the evidence that distinguishes them.

## OUTPUT_STALE — `SENSOR/source_slow`

**Observable symptom.** a timed channel's output is later than its function requires, or its timestamps are inconsistent

**Mechanism.** the source sampled later than its declared period, so the value was already old when it left

**Alternative explanations (other domains that can produce the same symptom).**

- `COMMUNICATION/transport_delay`
- `COMPUTE/processing_delay`
- `COMPUTE/process_stall`
- `TIMING/clock_inconsistent`

**Required distinguishing evidence.**

| direction | predicate | reads |
|---|---|---|
| confirms | `SOURCE_INTERVAL_NOMINAL_FALSE` | TIMING |
| refutes | `SOURCE_INTERVAL_NOMINAL` | TIMING |

## COMMAND_NO_RESPONSE — `SENSOR/response_sensor`

**Observable symptom.** an actuator was commanded and the measured response is weak or absent

**Mechanism.** the actuator is fine and the channel measuring its response is not

**Alternative explanations (other domains that can produce the same symptom).**

- `COMMUNICATION/command_not_delivered`
- `POWER/path_unavailable`
- `ACTUATION/drive_no_current`
- `ACTUATION/mechanical`

**Required distinguishing evidence.**

| direction | predicate | reads |
|---|---|---|
| confirms | `STALL_SIGNATURE` | ACTUATION |
| confirms | `PHYSICAL_RESPONSE_NOMINAL` | ACTUATION |
| refutes | `PHYSICAL_RESPONSE_NOMINAL_FALSE` | ACTUATION |

**Note.** resolvable ONLY where an independent physical channel exists. On a platform without one this hypothesis can never be eliminated, and the candidate set has an honest floor of two.
