## 4A — Structural rescue: FAIL

The proposed rescue is a relation that discriminates `nominal` from `gps_fault`
during fix loss while sitting outside the closing `gvalid` mask. Five findings,
in order of how completely each one closes the door.

**1. The target hypothesis has exactly one supporting feature.**
`CAUSES["gps_fault"] == ["phys_gps"]` (`csia/diagnosis/bayes.py`). There is no
second feature to fall back on.

**2. That feature is gated on the flag the fault zeroes.**
`P["gps"]` gate parses to `gvalid * (1.0 if tau > 3.0 else 0.0)`
(`csia/runtime/online.py:572`), and `P` is multiplied again by `fresh["gps"]`
at line 613.

**3. Its residual has no inputs during the window.**
`phys_gps` is `norm(_gps_fd_vel - vel)` — finite-differenced *reported position*
minus *Doppler velocity*, both from the GNSS receiver. Measured across the
committed fix-loss windows (450 ticks ArduPilot, 448 PX4), the usable share of
every GNSS channel is **0.000**:

| channel | ArduPilot | PX4 |
|---|---|---|
| `gnss.position` | 0.000 | 0.000 |
| `gnss.velocity` | 0.000 | 0.000 |
| `gnss.velocity_z` | 0.000 | 0.000 |

The logged `phys_gps` residual is `None` on every tick of the window, so even
the held step term (`_gps_step_peak`, which decays from pre-loss data)
contributes nothing.

**4. What survives cannot discriminate.** The relations still carrying weight
during fix loss on ArduPilot are `redundant_imu` (1.000),
`attitude_gravity_mag` (1.000) and `temp_bias_drift` (1.000). None takes a GNSS
input, so nothing makes any of them respond to a GNSS fault. In the brief's own
vocabulary they are `EVIDENCE_RELATION_NONDISCRIMINATING`. This is the core
dilemma, and it is structural rather than incidental:

> A relation sensitive to `gps_fault` must consume GNSS data, which fix loss
> destroys. A relation that survives fix loss consumes no GNSS data, which
> leaves it insensitive to a GNSS fault.

**5. The one exception is contractually forbidden.** `estimator.variances`
(ArduPilot `EKF_STATUS_REPORT`, `pos_horiz_variance`) *is* GNSS-fault-sensitive
and *does* survive fix loss — the estimator's position variance grows under
denial. It is ingested by the adapter and measured at 50.15 Hz on the driven
qualification link. It is nonetheless unusable, for two independent reasons:

- **Contract**: `csia_may_use: false`, with the reason recorded in
  `CHANNEL_SEMANTICS.yaml` — *"deliberately excluded from diagnosis. CSIA must
  not consume the estimator it is meant to be independent of. Logged for the
  autopilot-vs-CSIA comparison required by S9, and for nothing else."*
  Consuming it would dissolve the independence claim that is the layer's whole
  premise. This is a design invariant, not a technicality.
- **Empirics**: it was usable on **0 of 751 ticks** in both Mechanism A arms.
  The message is handled but never arrived on the shadow link — itself an
  instance of Mechanism C hitting the candidate that would have rescued
  Mechanism A.

Against the brief's PASS criteria: computable during the window **no**;
independent of the state fix loss destroys **no**. Two hard criteria fail, so
no candidate is carried forward. Per the brief, none was manufactured.

### What this actually means

This is not merely "we could not find a residual". It is a finding about the
architecture: **under fix-loss self-occlusion the only quantity that
discriminates `nominal` from `gps_fault` is the missingness event itself** —
`gnss.position.missing == NO_3D_FIX`. That is categorical, available on every
tick of the window, and independent of `gvalid`. It is precisely the gate-event
term of 4B, and it is not a residual, so it cannot be placed inside/outside a
gate for the matched ARM 2 / ARM 2C control the experiment depends on.

The structural-rescue arm and the gate-event arm are therefore not independent
alternatives here. They are the same observable, and only one of them is a
residual — which is the one the experiment needs and the architecture cannot
supply.

## 4B — Gate-event likelihood: INFEASIBLE for a scored empirical claim

`Z` would be the missingness reason on `gnss.position`. Estimating
`P(Z=z | H=h, C)` needs calibration observations and a calibration/test split.
The committed corpus contains:

| | count |
|---|---|
| flights with **any** `NO_3D_FIX` tick | **2** (`ap_FAULT`, `px4_FAULT`) |
| flights with none | 28 |

One fault flight per platform. A likelihood table fitted on it would be fitted
on the entire fault population, leaving nothing held out — exactly Reviewer 5's
objection, unanswerable. The brief's permitted fallback is taken. A synthetic
gate-emission model remains available as `MODEL-BASED SENSITIVITY, NOT
EMPIRICALLY CALIBRATED`, and is not pursued here because it cannot support a
scored empirical claim either.

## 4C — Sequential detector: PASS

`research/phase2/p1_offline_baselines.py` implements B4, already validated and
frozen, with parameters recorded in
`research/phase2/results/baseline_comparison.json`:

| parameter | value |
|---|---|
| detector | one-sided CUSUM on the standardised **pre-transform** residual (`OnlineTrustLayer._lam`, read-only) |
| drift `k` | 0.5 (textbook; half the one-sigma shift to detect) |
| decision interval `h` | 500.0 |
| `h` selection rule | smallest `h` from a fixed grid giving **zero** alarms on the clean nominal arm; evaluated on the clean arm only, never on a fault outcome |
| in-control statistics | clean nominal arm only |
| R10 clean alarms | **0** (`satisfies_R10: true`) |
| cost | 0.618 µs/tick |

It reads `_lam` read-only, so no frozen-core change is required, and a prior
`h = 5.0` failure (3 clean alarms) is retained as a committed negative result.
Porting it to current-stack traces needs `mu0`/`sigma0` re-derived on **clean**
current-stack data; 28 such flights exist, so calibration/test separation is
genuinely available here — unlike 4B.

## 4D — Transport starvation: PASS

Deterministically controllable, and already demonstrated three times across
independent boots (`research/v1_1/results/PX4_LINK_RATE_PROBE.json`):

| requirement | evidence |
|---|---|
| same platform/build | `PX4-Autopilot@547e2ca`, `sihsim_quadx` |
| same message source | `SCALED_PRESSURE` |
| controlled condition | presence/absence of `SET_MESSAGE_INTERVAL` on the consumer's own link, both arms in the same boot |
| measured delivery | passive **1.000 Hz** vs requested **9.775 Hz** |
| downstream freshness impact | baro node fresh 0.0967 vs 0.9992 on a driven link |

This is the strongest arm in the audit and the only mechanism that is fully
controllable on demand.

## 4E — Operating regime: DEFERRED

Crossing the `heading_course` gate needs sustained horizontal speed above
`GATE_SPEED_LO = 2.0 m/s`; the committed corpus maximum is 0.170 m/s. ArduPilot
can fly it, but it requires a new commanded-trajectory path in the rig plus a
new campaign. Feasible, not cheap. The brief forbids letting it delay the main
experiment, and the main experiment is stopped regardless.

## Consequence for the research question

The crossover experiment cannot be run **as specified**, because its causal
core — ARM 2 versus ARM 2C, the same residual differing only in gate placement
— requires a residual that this architecture cannot supply during fix loss.
Without that matched pair there is no causal test of gate placement, and
Reviewer 1's objection ("you added evidence, not moved a gate") would stand
unanswered.

Two of the four mechanisms remain independently controllable (B via the frozen
CUSUM, C via the link condition), so a **narrower** experiment is possible. It
would not be MAER: it could not test H1 or H3, which are the mechanism-
specificity hypotheses the whole design exists to test. Proposing that
substitution is out of scope for a feasibility audit, and the brief is explicit
that a condition which cannot be run must be marked and not substituted.

**The honest summary is that MAER's central claim may be untestable on this
architecture for a principled reason rather than a practical one.** If the only
discriminating observable under self-occlusion is the absence event itself,
then "restore the evidence structurally" has no referent — there is no evidence
to restore, only an absence to interpret. That is a real result about the
system, and it is the kind of result the brief says to keep.
