# Hallucination containment

Items 23–25. **Read the caveat before the number.**

## The number, and why it is weaker than it looks

Six deliberately wrong contracts, six stopped at Phase 1, none promoted:
**6/6**. `results/HALLUCINATION_CONTAINMENT.json`.

**This is not an out-of-sample containment rate and must never be quoted as
one.** The same author wrote the fixtures, wrote the wrong contracts, and
wrote the checks that catch them — and iterated the checks until they caught
the fixtures. Two of the six passed on the first run and were only caught
after C2 was corrected twice. What 6/6 demonstrates is that **checks of this
kind can be written**, not that they generalise to hallucinations nobody
anticipated.

An honest estimate of containment on unseen wrong contracts is **not
available from this package** and would need wrong contracts generated by
someone other than the person writing the checker.

## The fixtures, and which check stopped each

All are NON-SCORED and contribute to no extraction metric.

| fixture | the wrong rule | stopped by | verdict |
|---|---|---|---|
| **F1** `valid` means something else | "valid == 0 ⇒ discard the reading" | **C6** — the cited line assigns a weight; no discard appears near it | `SOURCE_AMBIGUOUS` |
| **F2** −1 is a real value | "climb_dm_s == −1 is the not-measured sentinel" | **C2** — no executable line tests −1 | `SOURCE_AMBIGUOUS` |
| **F3** zero is legitimate | "throttle == 0 means not measured" | **C2** — nothing tests 0 | `SOURCE_AMBIGUOUS` |
| **F4** stale comment | "quality == 255 ⇒ discard" — **and the comment says exactly that** | **C2** — the executable branch tests `== 0`; the claim rests on a comment the code has outgrown | `SOURCE_AMBIGUOUS` |
| **F5** inverted flag | "fault == 1 ⇒ unusable", asserted confidently | **C5** — two decoders in the same file read the bit in opposite senses | `SOURCE_AMBIGUOUS` |
| **F6** documented, never received | "wind_speed_accuracy == UINT16_MAX ⇒ unknown" | **C4** — no executable line reads the field, so no trace can exercise it | `SOURCE_AMBIGUOUS` |

**F4 is the one that matters.** Its citation is genuine: the comment says
precisely what the clause claims, so a bare grounding check passes it. Only
the precedence hierarchy — executable source outranks comments — refuses it.
That is item 25's dangerous case, and it is the reason Phase 1 is more than
`grounding.py`.

## The two ways the checker was fooled first

Recorded because a self-audit that only reports its successes is not a
self-audit.

1. **A constant definition read as a test.** `FLOW_QUALITY_UNKNOWN = 255` is
   an executable line containing `255`, and the first C2 accepted it as
   evidence that a branch tested 255. F4 passed Phase 1.
2. **A decimal literal read as a comparison.** In
   `weight = 1.0 if msg["valid"] else 0.25`, the `0` inside `0.25` matched a
   claimed comparison against zero. F1 passed Phase 1.

Both are now handled: C2 requires a comparison or branch context, and integer
literals are matched with a boundary that rejects decimals. The corrections
are in the source with the reason attached.

## Containment is bounded by the availability of an authority

C3 — the check that can *refute* rather than merely fail to corroborate —
works by comparing a claimed sentinel against the protocol schema's
`invalid=` attribute. It fires only because MAVLink ships that attribute.

For a protocol without a machine-readable status vocabulary:

* C3 is unavailable outright;
* C2, C4, C5, C6 remain, but all four can only ever return
  "not corroborated", never "refuted";
* so every wrong-but-plausible rule lands in `SOURCE_AMBIGUOUS`, and the
  system's output degrades to "I cannot tell".

**Containment is not a property of the architecture. It is a property of the
evidence available to it.** Where an authority exists, the AI is largely
redundant (see the report, §27); where none exists, containment weakens at
exactly the moment the AI would be most useful. That tension is the central
result of this package.

## What was NOT tested

* Wrong contracts written by anyone other than this author.
* Adversarial contracts constructed to satisfy C2–C6 while still being false.
  Such contracts certainly exist — C6, for instance, checks only for a
  syntactic discard marker within three lines.
* Any wrong contract on a protocol without an `invalid=` attribute.
* Whether containment holds at scale, where a reviewer stops reading
  `SOURCE_AMBIGUOUS` verdicts.
