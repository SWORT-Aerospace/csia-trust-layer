# Reality-gap audit (RB-001 Part 1)

**2026-10-02.**

- **Record:** `REALITY_GAP_AUDIT.json`, generated by `reality_gap_audit.py`.
  It has 10 claims and 59 threat rows, and covers every one of the brief's
  32 threats.
- **No evidence definition was changed** (the brief's rule for Part 1).

## 1. What simulation made artificially easy

| claim | the easy assumption |
|---|---|
| ESC telemetry response (q, L) | RPM is the simulator's rotor state: exact, instantaneous, unquantised; identical motors and propellers; rpm² exactly ∝ thrust through the same thrust model PX4 uses |
| allocator compensation (C) | a perfectly symmetric vehicle: no trim torque, constant mass, noise-free command split |
| steadiness (R, 2.3 r3) | gyro noise and vibration are tiny, so the peak body rate measures maneuvering only |
| rate transient (D) | a clean step in effectiveness, a clean gyro, an onset known to tens of ms |
| control-conditioned residual (B3/B4, research) | the setpoint is the applied torque; the angular-rate derivative is clean; inertia and effectiveness constant |
| battery source health | no current sensor: always UNAVAILABLE, so never tested in its NOMINAL meaning |
| PX4 monitors as triggers | almost no warnings in SIH flights |
| estimator status (2.2) | one PX4 version's message schema; one IMU, one EKF lane |
| log completeness | SITL logs had no dropouts at all |
| content time | publication time equals acquisition time |

## 3. Threats and the claims they touch

Count of rows per threat, from `threat_index` in the JSON:

| threat | claims affected |
|---|---|
| sensor noise | 5 |
| mechanical vibration | 4 |
| battery sag | 3 |
| CG uncertainty | 3 |
| wind, maneuver coupling, thrust nonlinearity, sensor mounting orientation, vehicle mass uncertainty, real PX4 scheduler behavior, calibration error, timestamp jitter, actuator saturation, propeller variation, control-loop variation, ESC telemetry latency, ULog dropout | 2 each |
| the other 16 threats | 1 each |

**Sensor noise and vibration dominate.** They break the closed-loop
statistics in a way recalibration only partly fixes, because the steadiness
statistic is a maximum.

**Mass and CG changes are the threat with no calibration answer.** The
compensation claim reads them as a loss.

## 4. What this audit says about what to test first

1. **The cheapest answers** come from RB2:
   - RPM against tachometer;
   - rpm² against thrust;
   - ESC telemetry latency;
   - current against shunt.

   They settle whether the telemetry claim transfers after recalibration.
2. **The closed-loop claims need RB5:**
   - compensation;
   - the steadiness condition;
   - B3/B4.

   No bench can test them.
3. **Two product-side weaknesses can be fixed once real propulsion logs
   confirm them**, with no hardware risk:
   - the version-specific estimator contract (partly done, RR-01);
   - the gap rule's reference interval.
